PICurv uses a robust locate-and-migrate pipeline so every particle ends each step with a valid owner rank and host cell, or is explicitly marked as having left the domain (EXITED) or as a search failure (LOST).

1. Core Search Concept

A particle is tested against candidate cell faces using signed distances. Search starts from prior cell information when available, then walks to neighboring cells by face-crossing logic until a terminal status is reached.

This avoids expensive global brute-force lookup and is suitable for distributed curvilinear grids.

2. Settlement Status Model

Location/migration logic uses ParticleLocationStatus:

  • NEEDS_LOCATION
  • ACTIVE_AND_LOCATED
  • MIGRATING_OUT
  • LOST - the search failed for a particle believed inside the domain
  • UNINITIALIZED
  • EXITED - the particle left through a face whose policy is remove

These statuses drive the iterative migration passes in the orchestrator. LOST and EXITED are final within one settlement: only pass 1 searches them, so a particle beyond the boundary is never re-walked and re-migrated pass after pass. Cleanup removes both and counts them separately (4.4 Loss and Exit Counters).

2a. Domain Boundaries

When a walk ends outside a boundary cell, the action depends on the crossed faces' particle_policy (5. Particle Boundary Policies):

  • any crossed face periodic (wrap): the particle is shifted by every crossed seam's translation at once and the walk moves to the cell at the other end of those axes, handing off to its owner if that cell is remote, so an edge or corner crossing of several seams needs one handoff; a wall crossed in the same corner reflects on the next evaluation;
  • otherwise, on a pass-1 walk that started from the particle's previous cell, an end more than three cell sizes beyond the face is treated as blocked by the domain's shape (a non-convex boundary between the start and the target), and the particle is searched again from scratch in the same pass;
  • any crossed face remove: the particle is EXITED;
  • all crossed faces reflect: the particle is mirrored about the most-crossed face plane and the cell is evaluated again, up to four reflections per search, after which it is placed just inside the boundary cell (counted as a reflection fallback). Only a cell warped so far that its centroid is outside the crossed face planes cannot take the fallback, and the particle is then LOST.

The rank owning a cell is found by a binary search of the decomposition's per-axis range starts (FindOwnerOfCell), so its cost does not grow with the rank count.

3. Implementation Touchpoints

  • single-particle walking search: LocateParticleInGrid
  • robust locate-or-migrate decision: LocateParticleOrFindMigrationTarget (walking-search module)
  • global orchestrator: LocateAllParticlesInGrid
  • rank migration communication: PerformMigration (sent particles are removed afterwards in one pass by RemoveFlaggedParticles, keeping the one-at-a-time survivor order; measurement swarm-one-pass-removal-2026-10-20)
  • owner of a cell: FindOwnerOfCell
  • wall reflection: ReflectParticleAcrossCellFace, with the cap fallback PlaceParticleInsideCell
  • restart fast-path migration: MigrateRestartParticlesUsingCellID

The current orchestrator includes:

  1. PID snapshot,
  2. per-particle locate/guess/verify,
  3. migration,
  4. newcomer flagging,
  5. repeat until no global migrations remain (or safety pass cap).

4. Restart Path Specifics

For restart-loaded particles with valid CellID, PICurv can skip full walking search and directly resolve owner rank via cell ownership map before migration. This is usually much cheaper than full re-location on first restart step.

6. Failure Modes and Signals

Watch for:

  • excessive migration pass counts,
  • repeated LOST particles (EXITED through an outlet is outflow, not a failure),
  • nonzero reflection_fallbacks, or many blocked_walk_retry_count events outside a strongly non-convex domain,
  • non-convergence of settlement loop,
  • elevated traversal effort or repeated tie-break/boundary-clamp events in <run.analysis.metrics>/search_metrics.csv,
  • increasing search_failure_fraction, search_work_index, or re_search_fraction,
  • increasing lost or lost_cumulative even when migration otherwise appears healthy.

For precise metric definitions and formulas, see Search Robustness Metrics Reference.

These usually indicate domain-decomposition mismatch, bounding-box mismatch, or invalid particle coordinates.
